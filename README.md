# Industrial Vision Anomaly Detection

Frozen DINOv2 + category-specific exact kNN for MVTec AD, with a shared
product classifier, open-set routing, anomaly maps, calibrated decisions, and
a CLI for one-image inference.

## What is implemented

1. A shared frozen `dinov2_vitb14` encoder produces one global embedding and
   normalized patch embeddings from one forward pass.
2. A multinomial logistic-regression classifier predicts one of the 15 MVTec
   product categories from global embeddings.
3. Validation-only confidence and nearest-global-distance thresholds reject
   inputs outside the known product distribution as
   `unknown_product_category` before a bank is loaded.
4. Each category uses its compatible normal patch feature bank and exact
   chunked Euclidean kNN. The image score is the maximum patch score.
5. Patch scores are interpolated to a `256×256` anomaly map. Image and pixel
   thresholds use category-specific 99th-percentile normal-only calibration.
6. Evaluation reports image/pixel AUROC and AP, plus thresholded precision,
   recall, F1, specificity, confusion matrix, Dice, and IoU when fixed binary
   decisions are supplied.

## CLI inference

The CLI does not require a manually supplied category:

```bash
PYTHONPATH=src DAenv/bin/python predict.py \
  --image datasets/mvtec_ad_processed/bottle/test/good/000.png \
  --device cpu
```

It prints JSON containing the predicted/accepted category, confidence,
nearest-global distance, reject thresholds, continuous anomaly score, image
decision (when threshold artifacts are provided), and heatmap path. Optional
calibrated artifacts can be supplied with `--image-thresholds` and
`--pixel-thresholds`. If they are absent, the CLI does not invent a threshold
or a `GOOD/DEFECT` label.

## One-command production run

Drop one MVTec-style dataset under `datasets/`. The folder name is not fixed;
the runner discovers it from the category/train, category/test, and
category/ground_truth structure. Then run:

```bash
PYTHONPATH=src DAenv/bin/python scripts/run_production.py
```

The command automatically validates and preprocesses the raw data, creates a
deterministic 70/30 train/validation split from `train/good`, builds compatible
normal feature memory/statistics, enables classification only when there are multiple
categories, runs category routing and Exact kNN as the image-level decision
authority, then runs separate PatchCore and PaDiM localization branches only
for DEFECT images.
The final report is written
automatically to:

```text
reports/production/<dataset-name>/<run-timestamp>/final_report.md
```

The same folder contains `final_summary.json`, classification/anomaly metrics,
CSV error analysis, confusion matrices, dataset distribution, and per-category
heatmaps. Use `--dataset-root` only when more than one valid dataset exists
under `datasets/`.

### Production orchestration and offline comparison

The production command always uses Exact kNN as the sole image-level decision
authority. PatchCore produces the production heatmap and PaDiM produces the
production binary mask only after Exact kNN returns `DEFECT`. Neither
localization model changes the GOOD/DEFECT decision:

```bash
PYTHONPATH=src DAenv/bin/python scripts/run_production.py

# Run all three independently on the same split and compare metrics/latency.
PYTHONPATH=src DAenv/bin/python scripts/compare_detectors.py --device cpu
```

The comparison command remains offline-only. PatchCore uses multi-layer DINOv2
fusion, local aggregation, and a seeded representative coreset. PaDiM uses
multi-layer fusion, dimension reduction, and per-position regularized Gaussian
statistics. Full implementation details are in
[MULTI_DETECTOR_IMPLEMENTATION.md](<AI config/MULTI_DETECTOR_IMPLEMENTATION.md>).

Production localization also writes two separate localization measurements:
the `heatmap` block evaluates the raw PatchCore heatmap against ground truth
with pixel AUROC/AP, while the `mask` block evaluates the refined PaDiM binary
mask with precision/recall/F1/IoU. The displayed heatmap is the raw PatchCore
map gated by the refined PaDiM mask. Small mask components are removed with a
3x3 opening by default; tune `--mask-min-component-area` and
`--mask-opening-kernel-size` when the defect scale changes.

## Egg detection + anomaly demo

The demo keeps complete-egg detection separate from quality anomaly scoring:
YOLO finds each full egg, then the existing DINOv2/PaDiM implementation scores
the cropped egg. The quality dataset is used only for image-level Good/Bad
evaluation; it has no verified defect masks.

The downloaded files are stored locally under `datasets/raw/` and ignored by
Git. Inspect them and write a compatibility report with:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py inspect \
  --config configs/egg_demo.json \
  --output reports/egg_demo/dataset_inspection.json
```

Prepare the original quality images. The command does not use the separate
augmented archive, and creates a deterministic 70/15/15 normal split:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py prepare-quality \
  --config configs/egg_demo.json
```

Install the optional YOLO dependency only when training or inference is
needed:

```bash
DAenv/bin/pip install -r requirements-egg-demo.txt
```

Train a small detector. The source dataset has only two validation images, so
this is a smoke/demo setup, not a final benchmark:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py train-yolo \
  --dataset-root datasets/raw/egg_detection \
  --weights yolo11n.pt --epochs 50 --imgsz 640 --batch 4 \
  --output-root artifacts/egg_demo/yolo
```

For the expanded detector experiment, combine the original detector set with
the labelled multi-egg archive, collapse both source egg colors into one
`egg` class, and add empty background crops as hard negatives. The script uses
the archive's official train/validation split instead of mixing the two. Use
GPU device `0` on a CUDA machine:

```bash
PYTHONPATH=src python scripts/prepare_egg_yolo_expanded.py
PYTHONPATH=src python scripts/egg_demo.py train-yolo \
  --dataset-root datasets/processed/egg_yolo_expanded \
  --weights yolo11n.pt --epochs 50 --imgsz 640 --batch 8 --device 0 \
  --output-root artifacts/egg_demo/yolo/expanded
```

The expanded model has one class (`egg`) and accepts only detections with
confidence strictly above `0.50`; the empty background crops reduce false
positives but do not replace a manually labelled negative hold-out set.

Evaluate the detector independently; Ultralytics reports precision, recall,
mAP50, and mAP50-95 for the two-image source validation split:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py evaluate-yolo \
  --dataset-root datasets/raw/egg_detection \
  --weights artifacts/egg_demo/yolo/<trained-weight>.pt
```

Build the normal DINOv2/PaDiM reference from prepared good eggs. Bad eggs are
not used for fitting or threshold calibration:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py build-reference \
  --processed-root datasets/processed/egg_quality \
  --artifact-dir artifacts/egg_demo/padim \
  --encoder-artifact-root artifacts/production/mvtec_ad
```

Build the combined production artifacts. This creates the `egg` feature bank,
extends the product classifier from 15 to 16 classes, and writes egg-specific
image/pixel thresholds without changing the existing MVTec artifacts:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py build-production
```

Evaluate PaDiM independently on the held-out quality images. This reports
image AUROC/AP only because the quality archive has no verified defect masks:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py evaluate-anomaly \
  --processed-root datasets/processed/egg_quality \
  --artifact-dir artifacts/egg_demo/padim \
  --encoder-artifact-root artifacts/production/mvtec_ad
```

Run one image or a directory. Each result contains the complete-egg box,
detector confidence, PaDiM score, and `GOOD`/`DEFECT` label; annotated images
and `predictions.json` are written under the output directory:

```bash
PYTHONPATH=src DAenv/bin/python scripts/egg_demo.py infer \
  --image path/to/egg_scene.jpg \
  --yolo-weights artifacts/egg_demo/yolo/<trained-weight>.pt \
  --padim-artifact artifacts/egg_demo/padim \
  --encoder-artifact-root artifacts/production/mvtec_ad \
  --output-root reports/egg_demo/inference
```

For a different product, change the JSON paths, class names, data preparation,
and model artifacts; the YOLO/crop/PaDiM pipeline does not contain egg-specific
processing logic.

## Important limitations

- The 99th-percentile thresholds control known-normal acceptance; they are
  not tuned for defect recall and must not use official test labels.
- A known defective product can be rejected as unknown if its global feature
  leaves the normal product distribution. The current routing policy is
  intentionally applied before category-bank inference.
- Full automatic-routing versus oracle-routing numbers require global test
  embeddings; the comparison helper is implemented, but no fabricated numbers
  are reported.
- Large datasets, DINOv2 weights, banks, and generated local outputs are not
  pushed to Git.
