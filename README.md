# Industrial Vision Anomaly Detection

Frozen DINOv2 + category-specific exact kNN for MVTec AD, with a shared
product classifier, open-set routing, anomaly maps, calibrated decisions, and
a CLI for one-image inference.

## What is implemented

1. A shared frozen `dinov2_vitb14` encoder produces one global embedding and
   normalized patch embeddings from one forward pass.
2. A multinomial logistic-regression classifier predicts one of the 15 MVTec
   product categories from global embeddings.
3. Validation-only confidence and nearest-global-distance thresholds reject
   inputs outside the known product distribution as
   `unknown_product_category` before a bank is loaded.
4. Each category uses its compatible normal patch feature bank and exact
   chunked Euclidean kNN. The image score is the maximum patch score.
5. Patch scores are interpolated to a `256×256` anomaly map. Image and pixel
   thresholds use category-specific 99th-percentile normal-only calibration.
6. Evaluation reports image/pixel AUROC and AP, plus thresholded precision,
   recall, F1, specificity, confusion matrix, Dice, and IoU when fixed binary
   decisions are supplied.

## CLI inference

The CLI does not require a manually supplied category:

```bash
PYTHONPATH=src DAenv/bin/python predict.py \
  --image datasets/mvtec_ad_processed/bottle/test/good/000.png \
  --device cpu
```

It prints JSON containing the predicted/accepted category, confidence,
nearest-global distance, reject thresholds, continuous anomaly score, image
decision (when threshold artifacts are provided), and heatmap path. Optional
calibrated artifacts can be supplied with `--image-thresholds` and
`--pixel-thresholds`. If they are absent, the CLI does not invent a threshold
or a `GOOD/DEFECT` label.

## One-command production run

Drop one MVTec-style dataset under `datasets/`. The folder name is not fixed;
the runner discovers it from the category/train, category/test, and
category/ground_truth structure. Then run:

```bash
PYTHONPATH=src DAenv/bin/python scripts/run_production.py
```

The command automatically validates and preprocesses the raw data, creates a
deterministic 70/30 train/validation split from `train/good`, builds compatible
normal feature memory/statistics, enables classification only when there are multiple
categories, runs category routing and Exact kNN as the image-level decision
authority, then runs separate PatchCore and PaDiM localization branches only
for DEFECT images.
The final report is written
automatically to:

```text
reports/production/<dataset-name>/<run-timestamp>/final_report.md
```

The same folder contains `final_summary.json`, classification/anomaly metrics,
CSV error analysis, confusion matrices, dataset distribution, and per-category
heatmaps. Use `--dataset-root` only when more than one valid dataset exists
under `datasets/`.

### Production orchestration and offline comparison

The production command always uses Exact kNN as the sole image-level decision
authority. PatchCore produces the production heatmap and PaDiM produces the
production binary mask only after Exact kNN returns `DEFECT`. Neither
localization model changes the GOOD/DEFECT decision:

```bash
PYTHONPATH=src DAenv/bin/python scripts/run_production.py

# Run all three independently on the same split and compare metrics/latency.
PYTHONPATH=src DAenv/bin/python scripts/compare_detectors.py --device cpu
```

The comparison command remains offline-only. PatchCore uses multi-layer DINOv2
fusion, local aggregation, and a seeded representative coreset. PaDiM uses
multi-layer fusion, dimension reduction, and per-position regularized Gaussian
statistics. Full implementation details are in
[MULTI_DETECTOR_IMPLEMENTATION.md](<AI config/MULTI_DETECTOR_IMPLEMENTATION.md>).

For a full-test heatmap experiment, use independent orchestration so every
test image receives a localization result. `dino_affinity` propagates each
detector's patch scores over frozen DINOv2 cosine affinity. The continuous-map
refiners `heatmap_open3`, `heatmap_open5`, `heatmap_open7`, and `heatmap_open9`
apply morphology before pixel thresholding. `--mask-postprocess open3` instead
changes an already-thresholded binary mask; these options are distinct. The
mask cleanup can be switched among `raw`, `open3`, `open5`, `open3_close5`,
`components`, `border2`, and `border5`. Pixel thresholds are calibrated from
normal validation images only. For example, to
evaluate the continuous-map opening without an additional binary-mask operation:

```bash
PYTHONPATH=src DAenv/bin/python scripts/run_production.py \
  --detector patchcore --orchestration independent \
  --heatmap-refiner heatmap_open5 --mask-postprocess raw \
  --device cpu
```

Affinity plus a binary-mask opening can be evaluated separately:

```bash
PYTHONPATH=src DAenv/bin/python scripts/run_production.py \
  --detector patchcore --orchestration independent \
  --heatmap-refiner dino_affinity --mask-postprocess open3 \
  --device cpu
```

The report separates continuous-map ranking from binary-mask metrics and keeps
PatchCore/PaDiM sources separate. It also records classification model
selection on validation (`C ∈ {0.1, 1, 10}`, 500 max iterations); the official test
split is never used to choose the classifier or thresholds. Existing
compatible embeddings and detector artifacts are reused unless `--force` is
specified. PatchCore and PaDiM cache reuse checks the detector settings,
category, image geometry, DINOv2 checkpoint hash, split-manifest hash, and
training-image content hashes; a mismatch triggers a refit.

On the full 15-category test split, the current independent PatchCore baseline
remains the selected heatmap method. With the same protocol, `PatchCore raw`
achieved pixel AUROC/AP `0.9596/0.4946`, while `dino_affinity + open3`
achieved `0.9486/0.4877`; binary-mask F1 was `0.3073` versus `0.2029`.
Affinity propagation also increased mean CPU latency from `0.2536` to
`0.3341` seconds per image. Therefore affinity is retained as an explicit
experiment option, not enabled as the production default, until a later
method improves both localization quality and false-positive control.

The same full-test run gives PaDiM a better binary-mask operating point but a
weaker continuous map: pixel AUROC/AP `0.9274/0.3943`, precision/recall/F1
`0.3515/0.6582/0.4583`, and IoU `0.2973`. This supports the intended
separation: PatchCore remains the continuous heatmap source and PaDiM remains
an independent binary-mask candidate; their metrics are not fused.

### 320px heatmap refiner transfer check

A later controlled run compared raw PatchCore with the screw-branch
`heatmap_open5` refiner on the same 15-category, 320×320 split. The refiner
changed pixel AP from `0.553759` to `0.553466` and thresholded F1 from `0.332078`
to `0.330809`; recall increased by only `0.089` percentage points. It was not
promoted. The 15-class product classifier remained at `99.826%` Top-1 on this
test set. The comparison report, per-category plots, exact-hash audit, and
artifact provenance are in
[`goal_15_category_transfer_heatmap_open5_320`](reports/experiments/goal_15_category_transfer_heatmap_open5_320/README.md).
The report is exploratory because this official MVTec test split had already
been used in prior method selection; a new locked holdout is still required for
an unbiased final claim.

The follow-up four-method comparison adds DINO affinity and Exact kNN to the
same split. Raw PatchCore remains the strongest recorded heatmap: macro Pixel
AP is `61.279%`; open5 is `61.243%`, DINO affinity `59.618%`, and Exact kNN
`53.464%`. See the [combined method table, category plots, and independent QA](reports/experiments/goal_15_category_heatmap_methods_320/README.md). The Exact
kNN test used the same split but omitted maps for three rejected images; all
test metrics remain exploratory because of prior MVTec test exposure.

The later same-resolution transfer benchmark keeps the exact-first workflow
roles: Exact kNN makes the GOOD/DEFECT decision, raw PatchCore supplies the
continuous heatmap, and raw PaDiM supplies the binary mask. On the 15-category
320px public MVTec test split, PatchCore raw leads continuous localization with
macro Pixel AP `61.28%`. PaDiM raw has the strongest balanced binary mask among
these outputs (macro Dice `42.66%`, precision `35.45%`, recall `71.01%`); a
PatchCore border5 mask has lower Dice (`32.23%`) but higher recall (`93.47%`).
Use `--heatmap-refiner` to switch continuous-map methods and
`--mask-postprocess` to switch binary-mask cleanup. The complete options and
per-category results are in
[the consolidated benchmark report](reports/experiments/goal_15_category_screw_heatmap_transfers_320_rerun4/HEATMAP_METHODS_CONSOLIDATED.md).
These test-selected comparisons are exploratory because the public MVTec test
split has been inspected in prior work.

## Important limitations

- The 99th-percentile thresholds control known-normal acceptance; they are
  not tuned for defect recall and must not use official test labels.
- A known defective product can be rejected as unknown if its global feature
  leaves the normal product distribution. The current routing policy is
  intentionally applied before category-bank inference.
- Full automatic-routing versus oracle-routing numbers require global test
  embeddings; the comparison helper is implemented, but no fabricated numbers
  are reported.
- Large datasets, DINOv2 weights, banks, and generated local outputs are not
  pushed to Git.
