# Clean holdout requirements — 15 MVTec categories

## Why the current scores are exploratory

The current 15-category experiments use the official MVTec AD test set. That set informed earlier method and resolution choices, so its scores cannot be treated as an untouched final estimate even though the current manifest and decoded-pixel audit find no exact cross-split duplicates. The exact-pixel audit does not establish absence of perceptual near-duplicates or acquisition-session leakage.

Current reference results:

- Heatmap baseline: raw PatchCore, **61.279% macro Pixel AP**. None of the tested screw-branch transfers improved Pixel AP.
- Product classification: frozen DINOv2 global embeddings with a multinomial logistic-regression head, **99.826% Top-1** on the exposed MVTec test; the three rejected predictions count as errors. This is a numeric pass for the current test only, not an unbiased generalization claim.
- The training embeddings cover 3,629 MVTec `train/good` images across 15 categories. A new split of these features could evaluate product-category recognition on held-out GOOD images, but not recognition of DEFECT images or anomaly localization.

## Proposed acceptance protocol — Project Owner approval pending

### Product classification

- Label every image with one of the 15 product categories, regardless of GOOD/DEFECT status.
- Define all-image Top-1 as correct known-category predictions divided by all known-category images; a rejected/`UNKNOWN` prediction on a known category counts as incorrect. Define macro Top-1 as the unweighted mean of the 15 per-category accuracies. Report both, per-category accuracy, and GOOD/DEFECT breakdown. At exactly balanced class counts the two point estimates coincide, which is intentional; their group-bootstrap intervals can still differ.
- Proposed gate aligned to the Project Owner's stated target: **observed all-image Top-1 and macro Top-1 both above 90%** on the sealed holdout. Report group-bootstrap 95% intervals as uncertainty summaries, not as pass/fail gates. If zero errors make a percentile interval collapse at 100%, label it degenerate; do not interpret it as proof that population accuracy is 100%. Any additional claim that a population lower confidence bound exceeds 90% requires a finite-sample cluster method and sample-size plan approved before collection.
- Since the system requirement is to reject products outside the known 15 categories, evaluate separate non-target validation and sealed-test sets. Define UNKNOWN false-accept rate as non-target images accepted as any known category divided by all non-target images; define known-product rejection rate as known images rejected divided by all known images. Use maximum class probability as the confidence score. On validation, choose the lowest rejection cutoff that meets the Owner-approved UNKNOWN false-accept cap, then verify known-product rejection stays within its approved cap. Freeze the cutoff before evaluating the sealed UNKNOWN set once. If no cutoff meets both limits, the candidate fails this operating-point gate.

### Heatmap localization

- For each category, compute Pixel AP over all evaluated pixels from that category's GOOD and DEFECT images; macro Pixel AP is the unweighted mean of the 15 category AP values. Keep raw PatchCore as the comparator.
- Align every score map and ground-truth mask to **320×320**, with no excluded pixels or ROI. Preprocessing resizes RGB images with Pillow Lanczos and masks with nearest-neighbor. The current patch map is bilinearly interpolated to the padded 322×322 canvas with `align_corners=False`, then cropped to 320×320; any candidate with a different output size must use the same 320×320 pixel grid before scoring. See [`preprocessing.py`](../../../src/mvtec_system/data/preprocessing.py) and [`maps.py`](../../../src/mvtec_system/anomaly/maps.py).
- Proposed improvement gate: at least **+1.0 percentage point** macro Pixel AP over raw PatchCore, with the paired group-level 95% confidence interval for the gain above zero and complete map coverage. This gate is a recommendation, not an approved project rule.
- Also report per-category Pixel AP/AUROC, defect-pixel recall (`TP/(TP+FN)` over defect pixels), and GOOD-image false-positive area (predicted-positive pixels divided by image pixels, averaged across GOOD images). Report macro category means for recall and GOOD false-positive area. Calibrate each method's per-category mask threshold as the q=.99 quantile of its known-normal validation pixel scores, matching the current benchmark protocol. The proposed AP gate alone does not certify binary-mask quality. The Project Owner must approve and preregister the recall and GOOD false-positive-area limits before the sealed test is unsealed; otherwise these operating-point results remain exploratory.
- Use validation data only to calibrate thresholds and select methods. Do not train, tune, or select a method using final holdout masks.

### Leakage and reproducibility controls

- Split by physical object and acquisition session. Build leakage groups as connected groups of records sharing either a physical object or acquisition session; keep every group intact within one split and use the same group unit for confidence intervals.
- Choose one candidate and freeze its source revision, weights, preprocessing, score aggregation, and validation-calibrated thresholds before revealing holdout results. Compare that preselected candidate with raw PatchCore on the sealed holdout. If multiple candidates are compared there and the winner is selected from those results, treat the comparison as exploratory and reserve a new holdout for the final claim.
- Preserve original images and masks, split manifest, group IDs, source and capture metadata, source revision, model/config hashes, validation thresholds, per-image predictions, and heatmaps.
- Compute exact byte and decoded-pixel hashes. Use a reviewed perceptual-near-duplicate process and group/session checks; exact hashes alone are insufficient.
- Proposed uncertainty summaries: generate 10,000 valid cluster-bootstrap replicates with seed `20261126`, each sampling the original number of leakage-connected components globally with replacement and keeping every image from each sampled component together, even when a component contains more than one category. Reject and count any draw that leaves a category without GOOD or DEFECT examples; do not silently omit that category or replicate. Rejected-draw rate is rejected attempts divided by all attempts; 10,000 means valid replicates after redraws. If the rejected-draw rate exceeds 1%, or a category has fewer than 20 independent GOOD-bearing or 20 DEFECT-bearing test components, mark the interval unreliable and collect more groups. For each valid draw, calculate separate descriptive intervals for all-image and macro Top-1, compute per-category heatmap metrics first and then their unweighted macro mean, and use identical component draws for paired candidate-versus-baseline comparisons. Report the 2.5th and 97.5th percentiles. These intervals do not provide a finite-sample guarantee at a zero-error boundary; flag such cases and do not use them as a population pass gate. This method, replicate count, seed, and invalid-draw rule are recommendations pending Project Owner approval.

## Data needed to close the 15-category claim

Preferred source: a new production-camera or independently collected set covering all 15 labels: `bottle`, `cable`, `capsule`, `carpet`, `grid`, `hazelnut`, `leather`, `metal_nut`, `pill`, `screw`, `tile`, `toothbrush`, `transistor`, `wood`, and `zipper`.

Proposed collection floor for planning, not a statistically proven minimum:

- Sealed test: at least 100 images per category, with at least 50 GOOD and 50 DEFECT, from at least 40 leakage-connected components per category. At least 20 components per category must contain GOOD samples and at least 20 must contain DEFECT samples. A mixed-category component remains intact and may count for every category it represents. This is a planning floor, not a power guarantee: in a simplified exact binomial check, zero errors among 20 independent groups gives a two-sided 95% lower bound of only about 83%; about 36 zero-error groups are needed for that simplified bound to exceed 90%. Real Top-1 and pixel metrics require group-level sample-size planning from a separate pilot.
- Development-validation data, disjoint from training and sealed-test components: planning floor of 100 images per category, at least 50 GOOD and 50 DEFECT, from at least 40 components per category (at least 20 GOOD-bearing and 20 DEFECT-bearing). It supplies GOOD images for q=.99 threshold calibration and masked DEFECT images for method selection.
- Development-training data: groups distinct from validation and sealed test. Any supervised refiner must have at least 20 GOOD-bearing and 20 DEFECT-bearing components per category in this partition, with empty/defect masks respectively; record actual image counts. It may use no validation or sealed-test masks for fitting.
- Original-resolution image for every sample; a pixel-aligned defect mask for each DEFECT image. GOOD images need an explicit GOOD label and an empty mask or equivalent unambiguous annotation.
- Manifest columns: `sample_id`, image path, category, GOOD/DEFECT label, mask path, physical object/group ID, acquisition-session ID, source, camera, lighting, capture date, and production lot where available. If the claim includes generalization across lots or capture days, reserve entire lots/days in the sealed test rather than only recording them.
- Keep augmented copies out of the holdout. For UNKNOWN evaluation, use separate validation and sealed-test sets, each with a planning floor of 100 non-target images from at least 20 groups; include both out-of-scope products and non-product/background crops, and keep groups disjoint. Set numeric false-accept and known-product rejection limits before the final test. Report group-bootstrap intervals for both rates; if zero observed events make an interval collapse at zero, mark the rate result inconclusive for a population-bound claim. Any upper-bound acceptance claim needs an owner-approved finite-sample cluster method and pilot-based group count before unsealing.
- If acceptance must include multi-product frames and detector crops, include the original frames and per-instance ground-truth boxes as an additional evaluation track.

More samples or groups may be required if the group-aware confidence intervals are too wide. Run a separate pilot and group-level precision/power calculation before freezing the final test size; the pilot must not become part of the sealed test. The collection floor does not guarantee that the acceptance gates will be met.

## Public dataset options found so far

| Dataset | Verified relevant content | Appropriate use and limitation |
|---|---|---|
| [VisA](https://github.com/amazon-science/spot-diff) | Twelve object subsets, including `capsules`; image labels and pixel annotations for anomalies; CC BY 4.0. | Useful as an independent cross-dataset check for the capsule family, subject to a source/hash audit. It covers only a subset of the target labels, so it cannot validate 15-category accuracy or 15-category macro Pixel AP. |
| [Real-IAD](https://realiad4ad.github.io/Real-IAD/) | Thirty object categories, anomaly masks, and an approximately 53 GB 1024×1024 archive. The [paper supplement](https://openaccess.thecvf.com/content/CVPR2024/supplemental/Wang_Real-IAD_A_Real-World_CVPR_2024_supplemental.pdf) shows toothbrush, transistor1, and zipper among 12 complex objects with five views; the remaining 18 simpler objects have two views. Defects are deliberately manufactured during dataset preparation. | Strong cross-dataset track for a few mapped product families, after verifying released files and keeping all views of each physical item in one split. It is not a full 15-category holdout and its manufactured anomalies do not establish performance on naturally occurring factory rejects. Research-only; the dataset card states CC BY-NC-SA 4.0. |
| [MVTec AD 2](https://www.mvtec.com/research-teaching/datasets/mvtec-ad-2) | Eight new scenarios with more than 8,000 high-resolution images; pixel masks are public for `TESTpub`, while larger private test labels are evaluated through the official server. | Independent anomaly-localization stress test under new scenarios and lighting, not a product-category test for the same 15 labels. |
| [MVTec LOCO AD](https://www.mvtec.com/research-teaching/datasets/mvtec-loco-ad) | Five categories with structural and logical anomalies and pixel-precise annotations. | Useful as a separate logical-anomaly evaluation. Its scenes and task differ from the 15 MVTec AD categories, so report it separately. |
| [KolektorSDD2](https://www.vicos.si/resources/kolektorsdd2/) | 356 defective and 2,979 defect-free images of one industrial surface/product, with several surface-defect types. | Can probe binary GOOD/DEFECT transfer on a different product. It cannot support the 15-way product classifier; confirm annotation granularity before using it for pixel-level heatmap metrics. CC BY-NC-SA 4.0. |
| [ADNet](https://grainnet.github.io/ADNet.html) | A unified benchmark of 380 categories aggregated from 49 public datasets, with MVTec-style masks and text annotations. | Potential broad transfer track, not a turnkey clean holdout for this project: audit the released source lineage and exact image/content overlap before use. It does not itself provide a fresh, verified holdout for these exact 15 labels. |
| [MVTec AD](https://www.mvtec.com/research-teaching/datasets/mvtec-ad) | All 15 target categories and pixel masks. | Retain as the reproducible in-domain benchmark, but label scores exploratory because its official test set has informed prior method and resolution choices. |

No reviewed public source has been verified to provide a fresh, independent holdout covering all 15 MVTec categories with defect masks. The practical public-data option is a **partial cross-dataset track** using VisA and selected Real-IAD product families; keep its per-dataset and per-category results separate from the MVTec 15-category score. For the full acceptance claim, collect new images from the intended camera/workflow, then freeze object/session-disjoint development and sealed test partitions before any tuning.

A read-only `ls -lO` check found these `DAenv` files marked `compressed,dataless`: `numpy/__init__.py`, `numpy/__pycache__/_expired_attrs_2_0.cpython-313.pyc`, `torch/__init__.py`, and `torch/ao/__pycache__/__init__.cpython-313.pyc`. A prior import attempt stalled while reading the NumPy bytecode; its full output was not saved as a repository log. No hydration, package install, or environment replacement has been performed. The current environment must be rechecked before any training run. A clean GOOD-only classifier split is not run yet; even if run, it would not validate DEFECT classification or heatmaps.

The Project Owner has been asked whether to provide a new 15-category holdout, use a partial public cross-dataset test, or keep the current numbers exploratory until new data are available.
